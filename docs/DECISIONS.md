# Design decisions

## Milestones 1–2 (historical baseline)

- The supplied document refers to companion `save.schema.json`, `balance.json`, and `example-save.json` files but includes only the genome schema and an empty checkpoint; use the exact supplied root envelope and genome fragment, define only the nested M1–2 fields in `src/sim/types.ts`, and do not claim full-schema compatibility.
- Use `src/sim`, `src/render`, `src/ui`, and `src/data` as requested; these replace the spec's more extensive module tree for this scope.
- Use localStorage and speeds 0/1/10/100 as explicitly requested, overriding the later IndexedDB and 0/1/2/4 requirements.
- Use rules version `0.2.0` and schema version 1 for this milestone subset; reject incompatible rules rather than silently interpreting complete-game saves.
- Run the small foreground core on the main thread in bounded batches; Worker scheduling, ownership/leases, offline catch-up and migrations belong to later milestones and are not implemented.
- Start one adult with hatch needs, neutral fixed personality, zero XP and a fixed neutral genome fixture; generated genes, expression, skills and lifecycle progression are deferred, so this adult does not age or die.
- Implement eat, graze, sleep, wander and idle only; play requires a partner and is deferred with social systems, and explore/training/preferences/learning are outside Milestones 1–2.
- Place four initial loose fruit (the first four common catalog entries) on safe land near the spawn; no replenishment or gardening is implemented, and unlimited grass grazing is the specified renewable survival fallback.
- Apply only each fruit's need effects; XP bonuses, exposure, tint and learned food preferences are later milestone systems and remain inactive.
- Keep unused root collections empty and autonomous breeding/immigration/offline settings disabled; these fields preserve the supplied envelope without activating future features.
- Retain the empty checkpoint's full inventory key sets with zero quantities as serialization placeholders only; no inventory features or additional fruit mechanics are active.
- The spec gives no minimum sleep work time other than the eight-tick commitment; allow sleep to finish below fatigue 15 after eight work ticks, and repeat 120-tick sleep while still tired.
- Save authoritative action target, remaining path and work ticks so mid-travel and mid-meal checkpoints resume exactly; no derived path cache or UI thought is serialized.
- Encode the normalized initial uint32 seed in `saveId` (`world_<seed>`); this keeps the supplied root keys and makes the debug seed recoverable independently of advanced RNG states.
- Save runner fractional time in `clock.fractionalSeconds`, including a bounded-batch backlog at 100×; pause retains this remainder and consumes no ticks, and hidden time is intentionally not simulated.
- Only the one-creature, empty-or-active-world subset is loadable; invalid JSON, references, paths, need ranges, RNG states, versions and counts are rejected before replacing live state.
- Arrival uses the travel interval only; full action work starts on the next tick so arriving never grants an extra full work tick.
- The singleton's loneliness continues to increase to 100 without a social outlet; this preserves the need formula while social behavior remains out of scope.
- Foreground timing is supplied by `requestAnimationFrame` and a saved accumulator; background throttling is handled by stopping hidden advancement, without adding the later Worker/offline system.

## Milestone 3: fruit and preferences

- The latest request's Milestone 3 overrides the spec's milestone table: implement fruit/preferences only, with no skills, genes, life stages, social behavior or appearance systems.
- The full companion schema is still absent; extend the existing root envelope with minimal typed source, food-memory and last-meal fields in `src/sim/types.ts` rather than claim full-schema compatibility.
- `fruits.json` replaces the earlier four-entry `fruit.json` and preserves all ten catalog rows; `skillBonuses`, their duration and `appearance` metadata are present but no effect subsystem reads them.
- `color` is the placeholder swatch; the separate inert `appearance.tintRgb` is reserved for future acquired tint, so drawing a fruit never activates an appearance effect.
- Store three seeded innate taste channels on each creature, normalize them and use them in place of §10.2's taste genes; Milestone 5 will replace this placeholder without adding gene expression now.
- Store learned means and sample counts and derive the displayed per-fruit scores; this avoids two mutable copies of the same preference.
- Use the literal §10.2 reward (taste enjoyment, pre-meal hunger and catalog stress relief); do not substitute a new post-meal nutrition formula.
- There is no time decay in §10.2; apply its fixed-rate learning and five-food repeat penalty only, so monotony can temporarily lower a score while its learned mean rises.
- The stable-repetition learning test warms up the five-meal window before checking direction, separating learning from the spec's initial monotony penalty.
- Increase passive hunger from 2 to 12 points/minute in `balance.json` for rules `0.3.0`: the old grazing balance produced no repeated meals, while the unchanged utility formula and catalog rates now sustain observable preference learning in the 20,000-tick test.
- Keep the six original common-plant positions and add four mature sources in the existing soil patch to cover every fruit; all growth rates/caps remain the spec's catalog defaults, without planting/harvest/build controls.
- Use `world.plants` for sources with `id`, `kind`, tile `x/y`, `matureAtTick`, `ripe` and `growthProgress`; reset progress at capacity and keep reserved fruit counted until the meal completes.
- An eating action optionally carries `targetPlantId` and claims one ripe fruit plus its adjacent approach cell; claims are derived from saved actions, so cancelling needs no second reservation ledger.
- Rank food opportunities by the existing utility formula before the four-food bound, instead of selecting only the nearest four, so a preferred fruit can influence which target is considered.
- Preserve the utility coefficients, temperature, hysteresis and self-care prerequisites; urgent hunger floors only negative food utility preferences at zero while actual meal feedback still records dislike.
- Schema 2/rules `0.3.0` migrates schema 1/rules `0.2.0` with neutral default taste weights, zero learned counts and default sources; keep clocks, RNG states, needs and existing actions unchanged.
- Migration places a source at the nearest safe free tile if its default overlaps a saved position/target/path; this preserves mid-action checkpoints instead of moving a creature or discarding its work.
- Keep the existing localStorage key so earlier saves are discovered; reject unknown versions and invalid claims, stock, preference memory or references before replacing the live state.
- Debug spawning is a pure capped command (three adults), using saved RNG for distinct taste biases and the unchanged fixed genome/zero-XP fixture; it adds no breeding, lifecycle or appearance behavior.
- Loneliness is not relieved by proximity even with three creatures, because social systems remain explicitly out of scope.
- Render a short meal reaction from the saved pre-meal preference for 12 ticks; table favorite/dislike labels still require the spec's three meals and thresholds.
- Fix the original first-hit canvas selection to choose the nearest creature, since adjacent debug-spawned individuals would otherwise always select the first one.
- Allow 15 seconds per Vitest test for the longer headless runs on shared cloud CPUs; a simultaneous Chromium run exceeded the old five-second budget without a behavioral assertion failing.

## Milestone 4: skills and training

- The request's milestone numbering overrides §15: add skills/training only, retaining immortal adults, three debug-spawn slots and zero starting XP rather than the full game's trained founders.
- §6 explicitly stores total XP only; levels, caps and progress are derived, avoiding inconsistent saved level/XP pairs despite the request's informal “level and XP” wording.
- No separate skill catalog/schema was supplied; `skills.json` defines the six specified IDs, names, action IDs, XP-curve coefficients and level caps using the existing typed config convention.
- Seed innate aptitudes independently from the world seed plus creature ID using an integer hash and xorshift32; spawning/migration do not advance existing creature streams, and Milestone 5 will replace this placeholder with gene expression.
- Use neutral configured boldness for fly/climb until personality genes exist; training preference starts at zero and learns via exact §5.4 wellbeing/level rewards, so no invented seeded interest is necessary.
- Capture wellbeing and starting skill level at the first work tick, retain them through saves, and learn only on ordinary completion; interrupted training retains earned XP but gives no completion reward.
- Apply exact §6 adult XP factors, aptitude cap, level taper, mood, fruit rate boost, need gates and 240-second daily practice limit; cumulative training includes all actual work, while daily counters reset after the boundary interval completes.
- Fixed training items use `world.items`, block their exact footprints, have capacity two and distinct adjacent claims derived from saved actions; no building/removal/inventory system is activated.
- Prefer available dedicated sites; use improvised land practice when their approaches/capacity are unavailable, and allow natural boulder practice for climbing. Candidate lists retain the specified two targets per skill and three path attempts.
- Add two shallow practice cells near the activity clearing in `training-spots.json`: the distant main pond never entered the top three candidates, so a nearby natural shoreline makes swimming observable without changing scoring or water-traversal gates.
- Increase passive boredom from 2 to 12 points/minute for rules `0.4.0`: at 2, growth interest dominated an almost permanently zero boredom deficit and several skills never received practice; this retains all utility/action/XP formula coefficients.
- Migration adds training items/practice water at nearest free safe locations when defaults intersect saved creatures, action targets or paths, preserving existing work and routes.
- Activate catalog fruit bonuses as percentages lasting 600 ticks; stronger/equal bonuses refresh expiry, weaker bonuses do nothing, and eating never mints direct XP. The interval ending at expiry receives its bonus before it is removed.
- Keep fruit appearance/exposure metadata, skill-driven body parts, advanced traversal modes, personality drift, genes, lifecycle, social systems and competitions inactive; they are outside the requested training milestone.
- Schema 3/rules `0.4.0` migrates schemas 1 and 2, adding zero skills/practice/learning and deterministic aptitudes while preserving existing XP, food memories, clocks, RNG and needs; derived levels are never trusted from saves.
- Debug skill edits are atomic, reject a level above the edited aptitude's cap and cancel only that skill's active training; deliberate edits can lower skills, while autonomous training never decreases XP.
- `npm run report -- [ticks] [seed]` uses Vite's existing Node TypeScript loader, advances the production pure core and reports levels, behavior work/travel time, training totals and need ranges without a DOM or new dependency.
- Earlier test assertions now expect the new schema version and filter newly added training kinds before checking the original five completed behaviors; their original survival, bounds and behavior requirements remain intact.
- Pacing target: first level 25 (1,450 XP) in roughly the first quarter of the specified 58,200-tick first lifespan, with continued diverse practice; retain base 1 XP/second, the exact 8L+2L² curve, caps 40+60q, and all catalog fruit durations/bonuses.
- Shorten the configured wander radius from 8 to 3 tiles: this keeps local wandering competitive alongside dedicated training while preserving the existing five-behavior integration check and all score coefficients.
- Generate one nearest free approach per dedicated item before bounding skill targets; multiple approaches to one item are capacity alternatives, not independent sites that should multiply its softmax weight.
- Milestone 4's final seed-271828 / 50,000-tick report: first level 25 at ticks 4,488 / 13,746 / 4,538 (7.7% / 23.6% / 7.8% of the 58,200-tick lifespan); top skills climb 66 / climb 44 / fly 57; all six skills trained, maximum hunger 68.60 and fatigue 55.68, both below the urgent gate of 85. These are the baseline before gene-derived traits replace the placeholders.

## Milestone 5a: genome and aptitudes

- The latest request defines 5a as genomes/expression and pure inheritance machinery only; there are still three immortal adult slots, with no breeding, life transitions, social systems, competitions or modular rig.
- The request explicitly says to store the genome on the creature, while §3.1 puts it on the organism; follow the request with one authoritative `creature.genome`, removing the organism's old fixture copy rather than keeping two mutable genomes.
- `genes.json` defines all 26 ordered loci, four chromosome memberships, allele/founder ranges, dominance modes, categorical intrinsic ranks/probabilities and phenotype ranges; logic reads this catalog rather than enumerating loci.
- Preserve the supplied four-chromosome/two-haplotype genome fragment; the missing companion full save schema still prevents a claim of complete-game schema compatibility.
- Pure genetics functions return the advanced RNG beside their result; new founders use the saved genetics stream, while creature/appearance seeds still use the saved world stream.
- `crossover` returns linked, unmutated parental gametes; `mutate` separately applies baseline §3.4 value/rank mutations and complete before/after records. Preview composes them in canonical parent-ID order; breeding will eventually own acceptance, exposure-aware meiosis and its committed draw ordering.
- Acquired mutation exposures remain inactive along with fruit appearance fields; no training or fruit changes genes, and mutation is called only on a detached offspring preview, never on a live creature.
- Derive normalized taste weights from the three taste genes; the phenotype also exposes all ten per-fruit genetic taste scores, while actual food preferences continue to include learned means and recent repetition.
- Derive aptitudes/caps, taste and personality baselines directly from the authoritative genome without a phenotype cache or saved derived values; remove the earlier random taste/aptitude generators, unused founder fixture and neutral personality config.
- Historical field names remain only in read-only legacy types and persistence validation/removal, because old saves must still load; the source-search test rejects those paths throughout active simulation, data, rendering and UI.
- Preserve experiential food/activity learning. Add §5.1 personality drift around gene baselines, its 20-day decay, and the +0.005 boldness reward for completing a new training activity with the specified 60-tick event cooldown; unimplemented social/exploration events give no rewards.
- Render the primary HSL color (base hue, saturation and lightness) on the existing shape; accent/eye colors, pattern, proportions, ears, trained parts and fruit tint/exposure stay inert for Milestone 7 or later.
- The existing aptitude debug tool now edits its two quantitative gene alleles, quantized to half-byte mean precision (1/510 for unit traits), then validates the resulting cap; it never writes a derived aptitude field.
- JSON spawning validates the complete catalog-shaped genome before atomically adding an adult; malformed input leaves the live habitat untouched and the three-creature cap applies to both random and imported founders.
- Offspring preview uses a copied user-visible seed and returns genome, phenotype and mutation records without changing population, any live RNG, XP or needs; it adds no breeding eligibility or parent/child life records.
- Schema 4/rules `0.5.0` migrates schema 3 and retains support for schemas 1/2; each historical creature gets a founder genome from a deterministic world-seed/creature-ID hash, with saved RNG streams, clock, needs, XP, work progress, boosts and learned memories preserved.
- Random migration aptitudes can otherwise invalidate existing XP; raise only the generated aptitude alleles needed to accommodate the current fractional XP ceiling, preserving XP and its integer level even above ordinary founder potential. This migration-only correction uses legal allele bytes through 255.
- Migrated aptitudes and taste bias necessarily change because genes cannot be reverse-derived from the old placeholders. Stored learned preference means, sample counts and history are preserved; displayed scores can change because the exact formula includes the new genetic taste term.
- Retune passive boredom from 12 to 9 points/minute for rules `0.5.0`: gene-derived curiosity now scales the rate per individual, and 9 preserves the earlier five behaviors, food-favorite variety and all-skill training tests without changing formula coefficients or fruit data.
- Render the practice-water label from actual saved terrain rather than its default location, so a source/action-preserving migration can relocate practice water without leaving a stale label.
- The final seed-271828 / 50,000-tick report has top skills Pip climb 43, Moss run 37 and Clover climb 55; first level 25 at ticks 13,538 / 19,034 / 5,879 (23.3% / 32.7% / 10.1% of the specified lifespan), all six skills trained, peak hunger 64.80 and fatigue 44.17. Lower founder aptitudes and autonomous self-care spread progression more than the earlier temporary-trait baseline; the exact 1-XP base rate/curve/taper are retained.
- Prior tests now construct hand-built traits through gene alleles and corrupt the creature's canonical genome; migration assertions expect schema 4 and gene-derived traits, preserving all earlier formula, survival, variety and replay assertions.

## Milestone 5b: life stages and death

- Add lifecycle/death only; real breeding, autonomous bonds, competitions, modular parts, acquired fruit appearance and advanced traversal remain outside this request.
- Use the exact first-life sequence egg 600 → baby 2,400 → juvenile 4,800 → adult 43,200 → elder 7,200 ticks: total 58,200 ticks (16 h 10 min at 1×), with no genetic timing modifiers or mortality variance because the spec defines none.
- Store total `age` ticks plus the existing stage boundary clock; `stageAtAge` derives transitions purely from age, with a separate cocoon-first path for reborn lives (1,200 + 2,400 + 4,800 + 43,200 + 7,200 = 58,800 ticks).
- Retain the earlier adult founder/debug-founder start for compatibility; founders begin at age 7,800, while debug eggs and all temporary replacements begin at age zero and pass through every first-life stage.
- Eggs/cocoons use `needs: null`, zero XP and no brain/work/welfare integration; hatch boundaries initialize needs/mood and cannot receive the elapsed interval's work twice.
- Apply the spec's hunger/fatigue multipliers baby 1.2, juvenile 1.1, adult 1, elder 0.9; XP multipliers 0.6/1.25/1/0.5 and stage caps 15/45/100/100; all babies can practice every skill, as §5.2 explicitly states.
- Normal stage transitions preserve XP, food/activity memory and personality drift; rising caps never reduce levels, and work at an earlier cap is not banked.
- Use stage scales baby 0.55, juvenile 0.78, adult 1 and elder 0.95; eggs/cocoons are separate oval placeholders rather than a modular body rig.
- The spec's elder performance multiplier 0.85 is retained in lifecycle data for later competition performance; it does not specify slower locomotion, so do not invent a movement-speed penalty from the request's illustrative examples.
- Choose elder saturation multiplier 0.45, cocoon saturation 0.6 and a 0.6-real-second departure fade to satisfy the requested visual cues; these presentation magnitudes are explicit additions in `lifecycle.json`.
- Departure fades are renderer-owned snapshots of the last seen creature, driven by render time and omitted from saves; the simulation and its RNG never depend on animation completion.
- Process aging/death boundaries after interval needs/work/mood/welfare and before ordinary completions/decisions; newly created eggs/cocoons receive no work or age from the creation interval.
- Rebirth is independent of breeding in §4, so implement its exact welfare ≥0.70, two living friends with bond ≥40, fewer than two prior rebirths, and one saved-creature-RNG roll at probability 0.60.
- Accept minimal existing relationship records solely for rebirth eligibility, retained bond scaling and death grief; no social behavior creates bonds yet, so ordinary default runs have no eligible rebirths.
- Rebirth closes the old life, creates a new creature ID for the same organism/genome, draws its new life stream once from world RNG, and starts a safe cocoon; reset XP/work/welfare/bonuses/history, retain name and learned sample counts, halve learned means/drift/bonds/mate bonds, quarter rivalry and retain familiarity.
- Permanent deaths close organism life and lineage records, remove the active creature/implicit claims, apply the specified friend valence/stress once and never depend on hunger/fatigue; pocket/cosmetic/competition systems do not exist and are not added for this subset.
- `autoReplaceOnDeath` is a default-on JSON setting copied into saved world settings and exposed as a debug checkbox; when off, a population with no rebirth eligibility dies out without immigration.
- **TEMPORARY until Milestone 6:** each permanent death self-crosses its genome, applies baseline mutation using the saved genetics stream and creates exactly one safe egg atomically in the vacated slot; no pairing, courtship or breeding eligibility is implemented.
- The request's “self-crossover plus mutation” and “differs only through mutation” conflict for heterozygous genomes: follow the explicit self-cross mechanism, permitting segregation of existing alleles, and test exact crossover/mutation results with no novel alleles except mutation.
- Lineage keeps creature ID, organism/name, null founder parents or one source creature ID for temporary descendants, actual spawn/birth tick, death tick, final stage, age at death, top skill/aptitude and ending reason; organism records retain their completed life lists after removal.
- Temporary descendants have one source-organism parent, deliberately outside the full game's zero-or-two-parent breeding contract; rebirth retains the organism and ancestry rather than making a new descendant.
- Raise the shared live-slot limit to eight, counting eggs and cocoons; keep dedicated item capacities and implicit claims unchanged. Extend configured speeds to 1000× with the existing bounded, saved-backlog runner.
- “Age selected by N ticks” advances the entire habitat through ordinary ticks, in yielding UI batches, so shared resources, time and lineage stay consistent; it never changes age directly.
- “Force stage” is an explicit separate debug override: reset its stage timer, clear the current action and clamp XP to a younger cap; forcing dormancy clears its needs/learned work, and a cocoon is valid only for a reborn life.
- Follow the selected organism's rebirth/replacement after death and rebuild roster buttons on ID changes, because a constant population count otherwise leaves stale dead IDs in the inspector.
- Schema 5/rules `0.5.1` migrates schema 4 to adult-start age 7,800 at the saved current tick, adds zero observed welfare and founder lineage, and preserves genomes, needs, XP, memories, clocks/RNG and in-progress actions; schemas 1–3 still migrate through their supported paths.
- Historical meals/level-ups/personality rewards validate against their life birth tick rather than the latest stage start, since normal transitions retain those memories; reborn histories can be empty while their informational sample counts remain retained.
- Split shared persistence checks and lifecycle validation into small modules to validate archive/parent/open-life references without expanding the earlier validator into one large module.
- `npm run report` now defaults to 500,000 ticks, samples stage populations every 50,000 ticks, and prints permanent deaths, rebirths, average canonical age at death, actual observed time alive and living top skill/aptitude; pre-aged founders explain the difference between age and observed duration.
- Earlier tests retain their numerical assertions, add non-null needs assertions for their pre-elder adult runs, expect schema 5/eight slots and keep a manually advanced day-boundary fixture's age consistent with its clock.
- The 300,000-tick, eight-slot test passed with population always eight, no hunger/fatigue reaching 100, exact old-age endpoints, valid replacement genomes and matching source lineage; default survival/variety assertions needed no balance changes.
- The seed-271828 / 500,000-tick report kept population exactly three, recorded 24 old-age deaths and no rebirths, and measured mean age at death 58,200 ticks (observed time alive 57,225 because founders begin as adults); peak hunger/fatigue were 73.40/50.18. Final top skills were strength 44 (aptitude 0.725), stamina 39 (0.565), and climb 54 (0.424).
- Sample report populations at stage-count changes as well as each 50,000-tick checkpoint so short egg/baby/juvenile periods remain visible; a 60,000-tick check shows exact cohort boundaries at 43,200 / 50,400 / 51,000 / 53,400 / 58,200.
- Wrap the expanded eight-creature roster and place the tick counter on a separate mobile playback row, so all slots and 1000× controls remain reachable at 320px.

## Milestone 6: breeding

- Follow this request's numbering: reproduction only; ordinary social bonds, rivalry, modular parts, competitions, construction and immigration remain inactive.
- The companion full save schema is still absent; extend the established plain-data envelope with breeding state, one courtship session, organism policies and explicit birth summaries in `types.ts` before implementation.
- §8.3's available compatibility terms sum to at most 0.45 without its required bond term, making its 0.45 threshold practically unreachable; normalize the original trait/taste/aptitude-difference weights (0.20/0.15/0.10) by their sum and retain threshold 0.45. The clearly marked Milestone 8 bond stub has JSON weight 0; waive the bond ≥30 entry gate until that system exists. Do not invent relationships, mate bonds or rivalry outcomes.
- Retain five expressed personality similarities (including drift), three raw expressed taste similarities and six aptitude differences; proximity bounds candidates, while mood/needs are eligibility gates. No attractiveness, skill or appearance factor is invented.
- Preserve §8.3 mate softmax at temperature 0.08, the minute-limited 0.25×compatibility×density proposal roll, ordinary utility competition, 0.35×compatibility court interest, recipient utility ≥0.25, and five-second decision staggering.
- Courtship uses the fixed welcome nest at (28,24), distinct adjacent targets, independent saved routes, 60-tick travel timeout and 40 work ticks. The nest is decorative rather than a new placeable item type so existing saved routes remain valid; construction and additional nests are outside scope. It supports one reserved egg slot/session at a time.
- Preserve adult-only entry, 41 adult ticks remaining at acceptance/work start, hunger/fatigue <55, stress <50, mood ≥0.1, five clutches per life, three-day cooldown, and the exact ancestor/two-generation shared-ancestor exclusion. Rebirth policies use permanent organism IDs.
- During shared work, urgent hunger/fatigue or invalid policies/stages cancel both participants; completion checks omit the 41-tick entry margin as specified. Lifecycle boundaries precede egg completion; travel never also grants work.
- Reproduction is sex-independent, with no carrier, pregnancy, delay or extra hunger cost: both parents receive total loneliness −15 and fatigue +2 over courtship work, and completion creates exactly one egg and gives both a clutch/cooldown. Acquired state is absent in newborns; existing 5a crossover then mutation functions are unchanged.
- Parent order is canonical organism-ID order; organism ancestry stores two organism IDs and the existing lineage `parentIds` stores the corresponding two creature-life IDs. Store mutation entries, generation and birth aptitudes alongside each life record for inspection/reporting after parents die.
- Delete the 5b death replacement setting, self-cross resolver, checkbox and replacement-specific tests. Historical settings are accepted only by the schema-5 reader and explicitly omitted from the migrated settings object; old replacement journal entries become ordinary historical spawn entries.
- Preserve historical one-parent ancestry as explicitly marked `legacy` records on migration rather than invent a second parent or erase family history; all new non-founder births require two parents. The old schema did not archive genomes, so unavailable deceased birth aptitudes migrate to zero and are not claimed as measured values.
- `extinctionRescue` is default on and spawns six unrelated founder eggs only when there are no active creatures, eggs, cocoons or sessions. Each egg has a prominent rescue event and founder lineage origin; disabling the saved flag permits a visibly extinct habitat. No periodic immigration is activated.
- Raise capacity to the specified 30, counting active eggs/cocoons plus accepted courtship reservations; all spawn/debug/command paths share that check. Use the specified density decline above 18 toward zero at 30.
- The requested food-scarcity test needs a supply signal beyond §4's head-count density: scale the soft breeding ceiling between 18 and 30 with the fraction of default renewable sources present, scale the full-rate boundary by that fraction, retaining the hard cap and grazing fallback; poor supply suppresses conception instead of causing death.
- Start the requested autonomous population with the spec's six unrelated founders (four adults, two juveniles), retaining zero XP from earlier milestones. Existing single-creature survival/training tests use an explicit one-adult fixture with breeding/rescue off to retain their original assertions.
- Pair implements the spec's exclusive pairing plus +0.15 utility and ×1.5 attempt encouragement; it does not force willingness, relatives, needs or life stage. Block overrides Pair/Encourage, including immediate cancellation; flags are removable and persistent. Individual encouragement uses the same nudge for that creature's pair candidates.
- `applyPlayerCommand` is the sole player breeding-policy/debug boundary, validates living organism IDs, returns a detached state and logs the exact plain-data command for deterministic replay. Debug Force breed bypasses eligibility/kinship, retains the hard slot cap and records its debug origin; it clamps informational clutch counts at the normal limit.
- Schema 6/rules 0.6.0 migrates schema 5 without advancing clocks/RNG or changing ages, genomes, needs, work or memories; initialize zero clutch/cooldown/attempt state and empty policies. Earlier schema migrations remain supported.
- Minimal performance fixes for the larger habitat cache derived navigation footprints and natural training cells; no authoritative state, RNG, paths or decisions is cached or serialized. Setup helpers copy cached terrain before edits.
- Pacing acceptance: a sustained nonzero population, never more than 30 slots, ongoing generations within the unchanged 58,200-tick first lifespan, no extinction rescue in healthy default runs, and final mean heterozygosity above 0.40 after 1,000,000 ticks. Keep original mutation probabilities 0.008/0.004/0.002 and three-day cooldown unless measurements require tuning.
- Diversity measures different allele **values** across each individual's 26 diploid loci (dominance ranks cannot inflate it); also report distinct active values per locus. Generations are one plus the maximum parent generation, so overlapping generations remain meaningful.

- The first two-source / 120,000-tick preflight with soft floor 6 rescued after kinship stalled births; raise the minimum soft ceiling to 18 (two sources imply 20.4) to preserve unrelated branches. The ten-source ceiling/boundary remain exactly 30/18, so default runs are unchanged.
- Keep shared travel paths directly on the courtship record, with ordinary `currentAction: null` from acceptance; this avoids duplicating routes in a new `join_session` action while preserving independent travel and exactly-once shared work.
- Entry margins and completion checks remain distinct; a route arriving on its 60th travel tick may start work on the next tick rather than being incorrectly timed out after already arriving.
- Compose the historical schema-5 setting key from fragments in its reader because this request explicitly forbids the retired literal anywhere in `src/`; the migrated current settings object is constructed without that key.
- The stability suite invokes the production report script directly with Node as its endurance harness so reporting and assertions use the same production run; all saves/ancestry/slot invariants are validated at each 50,000-tick checkpoint.
- A 50% source reduction (five sources) is the carrying-capacity comparison: its 120,000-tick preflight averaged 20.41 creatures with 45 births, no rescue and maximum hunger/fatigue 92.49/73.51. Severe 80% depletion can still lose viable family branches; rescue remains explicitly available for such unhealthy conditions rather than weakening kinship or wellbeing rules.

- The first seed-271828 / 1,000,000-tick report recorded 511 births, 488 old-age deaths, population 6–30 (last-100,000-tick mean 29.81), final heterozygosity 0.586 and no rescue. The specified attempt/density defaults produce occupancy near the hard cap; the spec’s nominal 12–24 range remains a balance target rather than a measured result.
- Track the minimum diversity at every birth/death membership change, covering every possible change during an autonomous run, and assert that minimum against the configured 0.40 floor.
- Correct the pre-existing preview to order parents by permanent organism ID, matching real conception even when rebirth creates a later creature-life ID; crossover and mutation functions are unchanged.
- Debug Force breed cancels either parent’s pending courtship, applies the full courtship need effects immediately, creates one egg and sets ordinary cooldowns; this keeps the resulting state immediately saveable.

- Run independent endurance worlds concurrently in separate Node processes, serialize Vitest files to protect short-test budgets, and kill unfinished report children during teardown; this uses the existing loader/dependencies and preserves deterministic world isolation.

## Milestone 7a: part and layer pipeline

- Follow the latest request's 7a scope: derived skill parts and a shared numeric scene only; full palette/proportion genes, static ear genes/patterns, fruit tint/exposure, idle clips, discovery logging and appearance caching remain inactive for 7b or later.
- “Reads skill levels and life stage only” conflicts with the explicit primary-gene tint requirement; read canonical derived skill levels/stage plus the existing base hue/saturation/lightness genes, with no other acquired or shape input.
- Use the exact 64×64 frame, anchors, skill mapping and painter order from §7.2; normalized body anchors resolve to body-centered coordinates and an affine matrix carries all final scale/rotation/offset/facing into each draw command.
- Recipe offsets and tail-tip attachments use frame units, primitive points are local, rotations are radians and layer indices are zero-based; these explicit units keep the numeric scene independent of its display size.
- The spec prevents skill parts from excluding each other and gives separate anchors; retain separate run feet, climbing hands, strength shoulders, swim fins, wings and stamina tail/crest slots, including the swim fan attached to the current stamina tail tip.
- The spec gives no general slot-conflict rule; highest eligible tier wins, then earlier `appearance.skillOrder`, then catalog order for a complete tie. Tests inject a conflict even though the default mapping avoids one.
