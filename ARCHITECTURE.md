# Derbil Dynasty 0.12

Vanilla TypeScript, Vite, Canvas 2D and Vitest; no runtime dependencies. Use Node 22.12+, `npm ci`, `npm run dev`. `npm run build` typechecks both the browser and headless dependency graph. `npm run test:dynasty` runs the current requirements' focused checks; `npm test` also includes historical milestone and long balance tests (see `docs/DYNASTY_VERIFICATION.md`). `npm run build:standalone` creates one self-contained HTML file.

`src/sim/types.ts` contains JSON contracts. `sim/tick.ts` clones state and orders resource growth, ordinary/shared actions, needs, lifecycle, settlements, social encounters, decisions and archive maintenance. `advance.ts` repeats exactly that tick. Saved world/genetics/competition/individual RNG streams own all gameplay randomness. The core has no DOM, Canvas, wall-clock or rendering imports and runs in Node.

`sim/` separates needs/utility/actions/navigation, genes, skills, lifecycle/lineage, breeding/kinship, social sessions and manual competitions. `sim/dynasty/` contains current energy, food interactions, fight modifiers, automatic Derby/Cup bookkeeping, defaults, migration of map positions and validation. Each berry has one saved ID and one owner/location. Temporary penalties do not modify XP or genes.

`sim/population.ts` uses the saved rescue preference for optional rescue based on projected survival and overlapping adult breeding windows; young Derbils and pending clutches suppress repeated assistance. `courtship-site.ts` finds nearby land for concurrent pairs; natural clutches create independent offspring genomes with bounded capacity. `sim/habitat.ts` staggers only new founder ages, permitting validated pre-world stage timestamps. Breeding tuning and mate persistence are covered by `npm run test:breeding`; `npm run balance:breeding` runs independent 300k-tick worlds (`--unassisted` disables rescue) and writes reproducible reports.

`src/data/*.json` owns balancing. Days are 60 ticks; egg/cocoon-to-expiry lives are 1,800 ticks. New founders include saved Daroboo. `data/config.ts` validates, types, hashes and freezes it; `dynasty.json` holds the new five-stat colors, movement, plants, social and scheduled-event defaults. `contracts.ts` describes each config field; regenerate `docs/TUNING.md` with `npm run tuning:doc` after changes. Game and save versions change deliberately, with documented migration decisions.

`src/assets/dynasty/` retains the original SVG bytes. `scripts/prepare-dynasty-art.py` extracts named groups into `render/dynasty-parts.json`; `prepare-dynasty-map.mjs` derives terrain and the approved flight closures. `render/dynasty-art.ts` retains exact SVG export recipes; its live renderer composes reusable Path2D groups from `render/vector-parts.ts` into bounded per-life canvases at device/zoom resolution. Eggs retain their embedded SVG highlight. Remaining SVG images have entry/pixel budgets. `render/scene.ts` paints read-only snapshots. `render/daylight.ts` smooths dawn/dusk and averages light at accelerated speeds, without changing simulation time. `render/camera.ts` and `ui/map-controls.ts` own map zoom/pan/picking; `render/ready-images.ts` retains decoded frames during asynchronous SVG changes. Animation and the force layout in `ui/social-layout.ts` are presentation state and cannot change simulation or RNG. The old numeric rig remains for historical tooling and tests; it is not the active Derbil artwork.

`ui/` contains controls, inspectors, graph and recovery views. `main.ts` owns browser orchestration. `app/time.ts` translates elapsed time; `app/foreground.ts` yields between exact ticks and retains adjacent snapshots for route interpolation in `render/movement.ts`. Speed changes discard unfinished wall-time debt; the toolbar reports achieved tick rate. `catchup.ts` handles offline replay, Skip and journal output. `app/` also owns tab arbitration and runtime guards. Navigation and genetic caches are derived data, never saved; genetic entries verify allele values before reuse. `sim/nearest-points.ts` returns exact Manhattan neighbors without full terrain scans. Offscreen painting is skipped while ticks continue. `npm run bench:long-play -- --world world.json --ticks 800000` checks an extended run, memory samples, state validation and save continuation.

`persistence/` owns IndexedDB/localStorage, verified spare-slot publication, rolling backups, quarantine, import/export and a codec worker. Envelope 14 checksums internal schema 12. The frozen `legacy/v1-v10.js` validates old catalogs before migration removes Climbing, combines relationship scores and projects positions onto the new map. Current saves round-trip without migration; older 40-plant worlds remain loadable and are thinned to the new 20-plant cap on their next tick. Changing worlds invalidates queued writes; only the owning tab may save. The schema11→12 calendar migration validates with frozen v11 rules, preserves stage fractions/history/RNG and converts calendar deadlines; historical units remain marked by dynasty.calendarChangedAtTick. Keep database keys and legacy fixtures stable.

Read `docs/DERBIL_REQUIREMENTS.md`, the Dynasty section of `docs/DECISIONS.md`, and `docs/STATUS.md` before continuing. The `source` branch contains the complete project; a separate `playable-preview` branch hosts the standalone ZIP. See `BUILDING.md` for setup and test commands.
